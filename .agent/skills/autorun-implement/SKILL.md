# Autorun Implement Skill

Skill especializado para implementar componentes del design system UBITS en templates HTML usando Storybook como fuente de verdad.

---

## 🎯 Cuándo Usar Este Skill

Usa este skill cuando:
- El usuario pide implementar un componente UBITS (Button, DataTable, Tabs, Input, etc.)
- Hay una imagen de diseño que incluye componentes UBITS
- Se necesita crear una interfaz con componentes del design system
- Se menciona cualquiera de los 80+ componentes disponibles

**Palabras clave que activan este skill:**
- "implementa", "agrega", "crea", "añade" + nombre de componente
- Referencias a componentes: Button, DataTable, Tabs, Modal, Input, etc.
- "desde Storybook", "usando UBITS"

## 🔄 Proceso del Skill

### Paso 1: Identificar Contexto

```typescript
// 1. Leer configuración de Autorun
const config = await view_file({
  AbsolutePath: '/path/to/Autorun/autorun.config.json'
});

// 2. Identificar del mensaje:
const analysis = {
  component: "Button", // ¿Qué componente?
  variant: "primary",  // ¿Qué variante?
  targetFile: "prototypes/canvas-objetivos.html", // ¿Dónde?
  functionality: "botón para guardar cambios" // ¿Para qué?
};
```

### Paso 2: Consultar Catálogo

```typescript
// Buscar ID de Storybook del componente
const catalogo = await view_file({
  AbsolutePath: '/path/to/docs/referencia/CATALOGO-COMPONENTES-UBITS.md'
});

// Ejemplo: Button → components-button--primary
const storybookId = "components-button--primary";
```

### Paso 3: Extraer desde Storybook

**Usar workflow:** `.agent/workflows/extract-storybook.md`

```typescript
await browser_subagent({
  TaskName: "Extract Component from Storybook",
  Task: `
    Navigate to https://ubits-storybook10.vercel.app/?path=/story/${storybookId}--implementation
    
    1. Extract HTML code from "Code" tab
    2. List all props/controls available
    3. Take screenshot
    4. Return extracted code
  `,
  RecordingName: "storybook_extraction"
});
```

### Paso 4: Crear Plan

```markdown
## Plan de Implementación: ${componentName}

### Información:
- **Componente:** ${componentName}
- **Variante:** ${variant}
- **Storybook ID:** ${storybookId}
- **Archivo:** ${targetFile}

### Tareas:
1. [ ] Insertar HTML en ubicación correcta
2. [ ] Configurar props: ${JSON.stringify(props)}
3. [ ] Aplicar tokens UBITS
4. [ ] Agregar event listeners (si necesario)
5. [ ] Validar visual y funcionalmente

### Props a usar:
${props.map(p => `- ${p.name}: ${p.value}`).join('\n')}
```

**⚠️ Mostrar plan al usuario y esperar aprobación antes de continuar.**

### Paso 5: Implementar

**Usar workflow:** `.agent/workflows/implement-component.md`

```typescript
await replace_file_content({
  TargetFile: targetFile,
  TargetContent: "<!-- Insertion point -->",
  ReplacementContent: `
    <!-- Generated by Autorun Skill -->
    ${extractedHTML}
  `,
  CodeMarkdownLanguage: "html",
  Instruction: `Implementar ${componentName}`,
  Description: `Agregado ${componentName} con props: ${JSON.stringify(props)}`,
  Complexity: 5
});
```

### Paso 6: Validar

**Usar workflow:** `.agent/workflows/validate-implementation.md`

```bash
# Lint
npm run lint

# Visual
browser_subagent → verificar renderizado
```

### Paso 7: Corregir Errores (si hay)

**Usar workflow:** `.agent/workflows/fix-errors.md`

Si validación encuentra errores, aplicar correcciones automáticas.

## 🚨 Reglas Críticas

### ✅ SIEMPRE:

1. **Consultar Storybook PRIMERO**
   - No inventar código
   - Usar Storybook en Vercel como fuente de verdad
   - Historia "implementation" es prioritaria

2. **Usar Tokens UBITS**
   ```css
   /* ✅ Correcto */
   color: var(--text-primary);
   padding: var(--spacing-md);
   background: var(--surface-secondary);
   ```

3. **NO Agregar Margin/Padding a Componentes**
   ```html
   <!-- ❌ MAL -->
   <button class="ubits-button" style="margin-top: 20px">

   <!-- ✅ BIEN -->
   <div style="display: flex; gap: var(--spacing-md)">
     <button class="ubits-button">
   ```

4. **Formato Correcto de Iconos**
   ```html
   <!-- ❌ MAL -->
   <i class="fa-solid fa-user"></i>

   <!-- ✅ BIEN -->
   <i class="fa-solid user"></i>
   ```

5. **Implementar UNA Tarea a la Vez**
   - No todo de golpe
   - Pedir aprobación entre tareas
   - Validar cada paso

### ❌ NUNCA:

- Inventar código sin consultar Storybook
- Agregar estilos arbitrarios a componentes
- Usar valores hardcodeados en lugar de tokens
- Implementar múltiples componentes sin plan
- Saltarse validación

7. **Resultado:** ✅ Botón implementado correctamente

## 💡 Tips para Usar Este Skill

### Tip 1: Componentes Múltiples
Si el usuario pide varios componentes, implementarlos UNO a la vez:
```typescript
for (const component of components) {
  await implementComponent(component);
  await validate();
  // Esperar aprobación antes de continuar
}
```

### Tip 2: Variantes
Si no se especifica variante, consultar Storybook para ver opciones:
- Button: primary, secondary, tertiary, ghost
- DataTable: default, compact, striped
- Modal: default, fullscreen, drawer

### Tip 3: Responsive
Algunos componentes tienen variantes responsivas. Verificar en Storybook si el componente debe comportarse diferente en mobile.
