GitHub

Integración completa con GitHub para gestión automática de repositorios. Auto-commit, gestión de ramas, historial de commits y más.

  • Auto-commit con cola de cambios
  • Gestión completa de ramas (crear, cambiar, mergear)
  • Volver a estados anteriores (checkout commits)
  • Merge a rama principal
  • Historial de commits
  • Estado del repositorio
  • Push automático (opcional)
Repositorio Git Debe estar en un repositorio Git inicializado
URL del Repositorio URL de GitHub (ej: https://github.com/user/repo)
Credenciales Git Configuradas localmente (SSH o HTTPS) 
{
  "autorun": {
    "addons": {
      "config": {
        "github": {
          "repositoryUrl": "https://github.com/user/repo",
          "branch": "main",
          "autoCommit": true,
          "autoCommitDelay": 5000,
          "commitMessage": "Auto-commit: {file}",
          "pushOnCommit": false
        }
      }
    }
  }
}
// Activar add-on
await hub.activateAddon('github');

// Usar servicios
const commitService = hub.getService('github', 'commit');
await commitService(['archivo1.js', 'archivo2.js'], 'Mi commit');

const pushService = hub.getService('github', 'push');
await pushService('main');
  • commit(files, message) - Hacer commit manual
  • push(branch?) - Push a rama
  • switchBranch(branchName) - Cambiar rama
  • createBranch(branchName) - Crear rama
  • listBranches() - Listar ramas
  • mergeToMain(branchName) - Merge a main
  • getCommitHistory(limit?) - Historial de commits
  • checkoutCommit(commitHash, createBranch?) - Volver a commit
  • getStatus() - Estado del repositorio
  • getCurrentBranch() - Rama actual

Este add-on soporta integración con MCP (Model Context Protocol) para mejorar la experiencia y seguridad.

  • Uso de APIs avanzadas de GitHub sin necesidad de tokens locales
  • Mejor gestión de credenciales y seguridad
  • Acceso a funciones avanzadas de GitHub

Figma Sync

Sincronización automática de tokens y componentes desde Figma. Importación de tokens, actualización automática e integración con Figma API y MCP.

  • Sincronización de tokens desde Figma
  • Comparación inteligente de tokens
  • Actualización automática
  • Integración con Figma API
  • Integración MCP (figma y talk-to-figma)
  • Soporte para JSON de tokens de Figma
  • Mapeo personalizado de tokens
  • Backup automático antes de sincronizar
Figma Access Token Token de acceso de Figma (obtener en figma.com/developers/api)
File Key Key del archivo de Figma a sincronizar
JSON de Tokens (Recomendado) JSON exportado desde el plugin de Figma Tokens (ver instrucciones abajo)

Ni MCP ni la API de Figma pueden acceder directamente a las Variables de Figma. Esta es una limitación de la API de Figma que no expone las variables directamente.

📥 Cómo Descargar el JSON de Tokens:
  1. Instalar el Plugin: Ve a Figma → Plugins → Browse all plugins → Busca "Figma Tokens" o "Tokens Studio for Figma" → Instala
  2. Configurar Tokens: Abre tu archivo de Figma → Plugins → Figma Tokens → Launch → Configura tus tokens
  3. Exportar JSON: En el plugin, ve a "Export" → Selecciona "Export tokens" o "Download JSON" → Guarda como figma-tokens.json
  4. Colocar en Proyecto: Coloca el archivo en la raíz de tu proyecto. El add-on lo detectará automáticamente en estas ubicaciones:
    • figma-tokens.json (raíz - recomendado)
    • tokens/figma-tokens.json
    • figma/variables.json
    • .figma/tokens.json
// El add-on buscará automáticamente el JSON de tokens
// Si lo encuentra, lo usará para mejor funcionamiento con MCP

✅ Figma Sync: JSON de tokens encontrado en figma-tokens.json
ℹ️  Este archivo permite que MCP y la API funcionen mejor con las variables de Figma
{
  "autorun": {
    "addons": {
      "config": {
        "figma-sync": {
          "accessToken": "tu-figma-token",
          "fileKey": "tu-file-key",
          "figmaTokensJsonPath": "figma-tokens.json",
          "figmaTokensPath": "../tokens",
          "projectTokensPath": "packages/tokens/tokens.json",
          "autoSync": false,
          "backupBeforeSync": true,
          "syncMode": "selective",
          "tokenMapping": {
            "figma.light.color.accent.brand": "light.brand.accent-brand"
          }
        }
      }
    }
  }
}

Nota: figmaTokensJsonPath es opcional. Si no lo especificas, el add-on buscará automáticamente el JSON en ubicaciones comunes. 

// Activar add-on
await hub.activateAddon('figma-sync');

// Comparar tokens
const compare = hub.getService('figma-sync', 'compare');
const comparison = await compare();
console.log(`Tokens sincronizados: ${comparison.synced.length}`);
console.log(`Tokens diferentes: ${comparison.different.length}`);

// Sincronizar tokens
const sync = hub.getService('figma-sync', 'sync');
const result = await sync({
  mode: 'selective',
  updateDifferent: true,
  addMissing: true
});
console.log(`Tokens actualizados: ${result.tokensUpdated}`);

CONECTAR

Conecta tu Hub

Guía paso a paso desde que clonas el repositorio hasta que despliegas tu aplicación

1

Clonar, Instalar y Configurar

Clona el repositorio Autorun, instala las dependencias del proyecto y las dependencias de Storybook. El sistema funciona con arquitectura dual: carga componentes desde Vercel (principal, requiere internet) y usa vendor/ubits/packages/ como fallback (funciona offline). El wizard configurará automáticamente el MCP de Storybook usando el paquete standalone storybook-mcp@latest. 

# 1. Clonar el repositorio Autorun
git clone https://github.com/elkingarcia22/Autorun.git
cd Autorun

# 2. Instalar dependencias del proyecto
npm install

# 3. Instalar dependencias de Storybook
cd vendor/ubits/packages/storybook
npm install

⚠️ IMPORTANTE: Ejecuta estos comandos en la TERMINAL, NO en el chat de Cursor.

¿Qué se instala automáticamente?
✅ Dependencias del proyecto Autorun
✅ Dependencias de Storybook (necesarias para que Storybook funcione localmente)
✅ El wizard configurará el MCP de Storybook usando storybook-mcp@latest (paquete standalone, más confiable)

¿Por qué necesitamos instalar dependencias de Storybook?
El MCP de Storybook necesita acceder al Storybook local corriendo en http://localhost:6006. Para que Storybook funcione, sus dependencias deben estar instaladas. El paso 3 es obligatorio si quieres usar el MCP de Storybook.

Nota sobre Storybook MCP: Después de instalar las dependencias, inicia Storybook con npm run storybook cuando quieras usar el MCP. El wizard configurará automáticamente el MCP para que Cursor pueda acceder a los componentes.

2

Inicializar el Wizard

Vuelve a la raíz del proyecto y ejecuta el wizard interactivo. El wizard te preguntará por el template, módulo, producto, navegación, add-ons, MCPs y GitHub, luego creará automáticamente ambos templates (administrador y colaborador) y configurará los MCPs. 

# Volver a la raíz del proyecto
cd ../../../

# Ejecutar el wizard interactivo
npm run init

⚠️ IMPORTANTE: Ejecuta este comando en la TERMINAL, NO en el chat de Cursor.

💡 Por qué en la terminal: El wizard necesita acceso interactivo a stdin/stdout para leer tus respuestas. El chat de Cursor no puede proporcionar input interactivo correctamente. Ejecutar en la terminal garantiza que puedas responder todas las preguntas.

El wizard te preguntará:

  • 🎯 Template: Administrador o Colaborador
  • 📦 Módulo y Producto: Selecciona el módulo (Aprendizaje, Desempeño, Empresa, Encuestas, etc.)
  • 🔒 Navegación: ¿Desactivar navegación a otros módulos? (útil para evitar que el usuario se pierda)
  • 🔌 Add-ons: Instalar solo los por defecto o agregar otros
  • 🤖 MCPs: ¿Instalar y configurar MCPs automáticamente? (Storybook, Figma, Supabase, Vercel, GitHub, Clarity)
  • 🐙 GitHub: ¿Configurar GitHub ahora? (opcional)

¿Qué hace el wizard automáticamente?
✅ Carga componentes desde Vercel (principal, requiere internet)
✅ Usa vendor/ubits/ como fallback (si no hay internet o Vercel falla)
✅ Clona y verifica repositorio UBITS (si no existe vendor/ubits/)
✅ Instala add-ons seleccionados
✅ Configura MCPs automáticamente (si aceptas)
✅ Crea archivo .cursor/mcp.json con todos los MCPs
✅ Storybook MCP usa storybook-mcp@latest (paquete standalone, más confiable)
✅ Configura sidebar y subnav para tu módulo
✅ Crea ambos templates (administrador y colaborador)
✅ Valida templates creados
✅ Abre solo el template seleccionado en el navegador

¿Necesitas un Add-on Adicional?

No te preocupes si olvidaste activar algún add-on. Cuando lo necesites, simplemente ejecuta el comando de activación y el sistema te solicitará las credenciales necesarias en ese momento. 

# Activar un add-on cuando lo necesites
npm run addon:activate [nombre-del-addon]

# Ejemplo: Activar Supabase más tarde
npm run addon:activate supabase
